**Goal:** A public read-only board API on apps/web and a native Expo app rendering the weigh-in-board world: board list with the four SOW filters, and registry-plate profile screens with D-2/V-3-compliant copy.

**Architecture:** `apps/web/lib/board-data.ts` becomes the single board-assembly source (directory page + new `GET /api/board`). `apps/mobile` is created with the current stable Expo SDK + expo-router; tokens mirror `packages/ui/src/tokens.css`; screens fetch `/api/board` once and render from memory. Spec: `docs/superpowers/specs/2026-09-05-expo-slice1-design.md`.

**Tech Stack:** Next.js route handler, Expo (current SDK) + expo-router + TypeScript, @expo-google-fonts (Oswald/Archivo/Martian Mono), vitest (web).

**Binding conventions:** commits `[ai-assisted] … (rule IDs)`; all copy through `pnpm compliance:check` (M-1) — the lint already scans apps/mobile; no ordinals/rankings on the board (M-2/P-4); D-2 on every profile; V-3 verification wording verbatim from web; never render or log storage keys (V-2).

**Scaffold-freshness rule:** where this plan says "per current Expo defaults," the implementer follows what today's `create-expo-app`/Expo docs generate rather than inventing config — and proves it with the `expo export` gate. Deviations from this plan's literals that come from current Expo defaults are expected and should be reported, not avoided.

```ts
import "server-only";
import type { CrewCardData } from "@crewmarket/ui";
import seed from "../data/seed-crew.json";
import { credentialOverrideMap, type PublicCredential } from "./credential-overrides";

/* The one board-assembly source: the directory page and GET /api/board must
   never disagree about what the public sees (V-1 board/profile agreement;
   V-2 — only PublicCredential fields ever cross this boundary). */

export function mergeBoard(
  profiles: CrewCardData[],
  overrides: Map<string, PublicCredential[]>
): CrewCardData[] {
  return profiles.map((c) =>
    overrides.has(c.id) ? { ...c, credentials: overrides.get(c.id)! as CrewCardData["credentials"] } : c
  );
}

export async function boardData(): Promise<CrewCardData[]> {
  const all = seed.profiles as unknown as CrewCardData[];
  return mergeBoard(all, await credentialOverrideMap());
}
```

- [ ] **Step 1: Types + fetch + pure filter fn** (`lib/board.ts`):

```ts
/* Wire types for GET /api/board — mirrors the web's CrewCardData JSON shape. */

export type BoardCredential = { kind: string; licenseClass?: string; expiresAt?: string; verified?: boolean };
export type BoardProfile = {
  id: string;
  displayName: string;
  roles: string[];
  homePort: string;
  dayRateUsd: number;
  yearsExperience: number;
  credentials: BoardCredential[];
  availability: { date: string; status: string }[];
};

import { API_URL } from "./api";

export async function fetchBoard(): Promise<BoardProfile[]> {
  const res = await fetch(`${API_URL}/api/board`);
  if (!res.ok) throw new Error(`board fetch failed: ${res.status}`);
  const json = (await res.json()) as { profiles: BoardProfile[] };
  return json.profiles;
}

export type BoardFilters = { role: string; port: string; date: string; verifiedOnly: boolean };

/* Same semantics as the web directory filter — keep in lockstep. */
export function filterBoard(profiles: BoardProfile[], f: BoardFilters): BoardProfile[] {
  return profiles.filter((c) => {
    if (f.role && !c.roles.includes(f.role)) return false;
    if (f.port && c.homePort !== f.port) return false;
    if (f.date && !c.availability.some((a) => a.date === f.date && a.status === "OPEN")) return false;
    if (f.verifiedOnly && !c.credentials.some((cr) => cr.verified)) return false;
    return true;
  });
}
```
